# Output Directory & Artifact Specification

**Standard**: Universal Autonomous AI Governance Operating System (UAIGOS 3.0.0)  
**Authority**: Ujomor Systems Engineering & Governance Authority  
**Classification**: GOVERNMENT | ENTERPRISE | RESTRICTED  

---

## 1. Executive Summary

This specification dictates the directory structures, purposes, producers, consumers, and data retention policies for all output artifacts generated by the Enterprise Autonomous Observability & Regulatory Compliance System (EAORCS). Strict adherence to these directory boundaries ensures compliance with zero-trust architectural principles and data sovereignty constraints.

---

## 2. Master Directory Matrix

The following table defines the official lifecycle and governance metadata for all dynamically generated output directories in the EAORCS environment, satisfying Section 5.3 of the Product Packaging & Generation Workflow.

| Directory | Purpose | Producer Component | Consumer Component | Retention Policy |
| :--- | :--- | :--- | :--- | :--- |
| `storage/evidence/` | Cryptographic audit payloads | Evidence Engine | Audit & Certification | Permanent (Ed25519 Signed) |
| `storage/telemetry/` | Runtime metrics & traces | Telemetry Engine | Dashboard Observatory | 90 Days Rolling |
| `storage/logs/` | System execution logs | System Logger | Diagnostic Doctor | 30 Days Rolling |
| `release/` | Deployable audit ZIP & attestations | Package Builder | Procurement Authorities | Immutable per Release |
| `docs/audits/` | Generated audit Markdown reports | Report Generator | External Auditors | Permanent per Release |

## 3. Directory Specifications & Lifecycle Management

### 3.1 `storage/evidence/`
**Purpose**: Storage of non-repudiable, cryptographically signed audit payloads and compliance artifacts.
- **File Naming Standard**: `evidence_[DOMAIN]_[TIMESTAMP]_[HASH].json`
- **Example**: `evidence_security_20260802T120000Z_a8f9b2c.json`
- **Producer**: EAORCS Evidence Engine (`engine/evidence/`)
- **Consumer**: EAORCS Audit & Certification Engine, External Regulators
- **Retention Policy**: Permanent. Files are immutable once written.
- **Audit Trail Verification**: Every file must contain an attached Ed25519 signature payload in its footer. Deletion or modification triggers an automatic governance violation alert via the Telemetry Engine.

### 3.2 `storage/telemetry/`
**Purpose**: High-frequency runtime metrics, OpenTelemetry traces, and synthetic dataset streams.
- **File Naming Standard**: `telemetry_[TYPE]_[DATE].jsonl`
- **Example**: `telemetry_traces_20260802.jsonl`
- **Producer**: EAORCS Telemetry Engine (`engine/telemetry/`)
- **Consumer**: EAORCS Dashboard Observatory, Prometheus, Datadog
- **Retention Policy**: 90 Days Rolling. 
- **Auto-Pruning Rules**: A background chron job (`bin/prune_telemetry.js`) evaluates file timestamps nightly at 00:00 UTC and securely wipes (DoD 5220.22-M standard) files older than 90 days.

### 3.3 `storage/logs/`
**Purpose**: Diagnostic system execution logs, debug traces, and generic application outputs.
- **File Naming Standard**: `eaorcs_syslog_[DATE].log`
- **Example**: `eaorcs_syslog_2026-08-02.log`
- **Producer**: System Logger (`utils/logger.js`)
- **Consumer**: Diagnostic Doctor (`bin/eaorcs_installer.js doctor`), SIEM Integrations
- **Retention Policy**: 30 Days Rolling.
- **Auto-Pruning Rules**: Logs are rotated daily. Archives exceeding 30 days are automatically deleted unless flagged for legal hold.

### 3.4 `release/`
**Purpose**: Target output directory for official GA readiness certification packages and baseline closure attestations.
- **File Naming Standard**: `eaorcs_[RELEASE_TYPE]_package_[VERSION].zip`
- **Example**: `eaorcs_pep_audit_package_2026.1.0-lts.zip`
- **Producer**: Package Builder (`bin/create_eaorcs_package.js`)
- **Consumer**: Procurement Authorities, Enterprise Customers
- **Retention Policy**: Immutable per Release. These packages serve as a historical snapshot of compliance at the moment of software distribution.
- **Audit Trail Verification**: The `GA_BASELINE_CLOSURE_ATTESTATION.json` within this directory must match the cryptographic hash of the enclosed ZIP archive.

### 3.5 `docs/audits/`
**Purpose**: Human-readable, formatted Markdown audit reports generated from raw evidence telemetry.
- **File Naming Standard**: `[PHASE_ID]_[AUDIT_TYPE]_REPORT_[VERSION].md`
- **Example**: `PHASE_12_PEP_EXTERNAL_AUDIT_REPORT_2026.md`
- **Producer**: Report Generator (`bin/generate_audit_report.js`)
- **Consumer**: External Auditors, Chief Information Security Officers (CISOs)
- **Retention Policy**: Permanent per Release. 
- **Lifecycle Management**: Reports are version-controlled alongside the repository and are treated as legally binding representations of system state at the time of publication.

## 4. Verification

Compliance with this specification is evaluated dynamically during the GA Readiness Certification pipeline.

```bash
node bin/ga_readiness_certification.js --suite directory-integrity
```

The certification process asserts:
1. All directories exist and possess correct RBAC permissions.
2. Unrecognized directories or files are flagged as taint.
3. Retention pruning algorithms are active and responsive.
